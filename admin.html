The item master file holds the fixed data of each material: description, category, unit of measure, owner BU and sector usage, supplier, cost, lead time, MOQ and photo. Stock quantities are in Stock Overview; planning levels are in Min / Max & Safety Stock. “Incomplete” means the supplier, unit cost, lead time or consumption history is missing; without these the safety stock calculation is unreliable.

Periodic parameter review

Method: d = average daily demand from history · σd = daily demand std-dev · LT / σLT = lead time & its variability (days)
SS = Z × √(LT·σd² + d²·σLT²) · Min (ROP) = d·LT + SS · EOQ = √(2·D·S / (H·C)) · Max = Min + max(EOQ, d·Review period) rounded up to MOQ. Z comes from the service level set per ABC class. Items with Z-class (erratic) demand are flagged for manual judgement.
Order-up-to-Max policy: items at or below Min are suggested; quantity = Max − position, rounded to MOQ.

Publishing to GitHub

Everyone opens the same data file (data/nacita-data.json) in the GitHub repository. Your edits stay in this browser until you click Publish; GitHub then updates the file and every viewer sees it within about 1–2 minutes. Publishing needs a GitHub access token, which is saved only in this browser.

Data

Excel mass upload: download the template, fill the Materials sheet (instructions and examples are in the other sheets), then upload it with Mass upload. To bulk-update existing items, export the current materials to Excel, edit, and re-upload with “Add new + update existing”. Monthly consumption goes in columns M1 (oldest) … M6 (latest) (add M7–M24 if you have more). The Excel reader loads from the internet on first use; CSV works offline.
CSV columns: code,name,bu,sectors,category,uom,supplier,unitCost,leadTime,ltStd,moq,onHand,onOrder,reserved,ss,min,max,hist — bu (owner) is one of WH, LM, FT, IOR; sectors lists every BU using it (e.g. WH;LM, blank = owner only); hist is monthly consumption, oldest→newest, separated by ; (e.g. 120;135;98;140;110;125). Import merges by material code. Your changes are kept in this browser until you Publish them; the JSON backup is a full copy you can keep or restore later.
